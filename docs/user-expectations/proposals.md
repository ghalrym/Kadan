# Open and stacked proposals

These proposals preserve product direction, not promises of current functionality. Status was checked against master `ab8681a91eec7ca0bf937d8e63be67e48c0eb0c2` on 28 October 2026 using commit ancestry and the implementation. ## Capabilities absent from master

- [#399](https://github.com/ghalrym/Kadan/pull/399): Persistent project plans, status tags, supporting documents and agent document updates. Plans retain progress, blockers and pending user decisions across later responses. This remains bounded response work, without automatic waking or indefinite execution.
- [#406](https://github.com/ghalrym/Kadan/pull/406): Save a computer file as a verified, agent-owned Workspace asset and deliver its download in chat. Uncertain uploads must be checked rather than repeated; stopping cannot undo an in-flight save.
- [#408](https://github.com/ghalrym/Kadan/pull/408): Copy a saved Workspace file to a separate verified temporary computer path. Preserve the stored original and changed local copies; report incomplete transfers and inspect uncertain outcomes before another copy.
- [#409](https://github.com/ghalrym/Kadan/pull/409): Upload files in the composer, attach them to a message or note and recover conversation-scoped drafts and uncertain uploads/sends. Removing a draft attachment would not delete the stored asset; lost local bytes would require reselecting the original.
- [#417](https://github.com/ghalrym/Kadan/pull/417): Download the saved conversation as a Markdown snapshot, with saved messages, attachment references and clear export limits. This would not provide a full backup or automatically include unsaved drafts or attachment bytes.
- [#439](https://github.com/ghalrym/Kadan/pull/439): Start an unsaved copy of a Tsuchi persona, memory, Space, deck or conversation. The source remains intact; saving creates a new record, preserves supported content/links and reports invalid dependencies. Copying would not run inference or replay conversation actions.

The file stack ends at open #399: #409 merged into #408's branch, #408 into #406's branch, and #406 into #399's branch. Their merge commits are not ancestors of the checked master. The focused [file delivery](kadan/file-delivery.md) and [opening files](kadan/opening-workspace-files.md) expectations describe the separately extracted transfer capability; the [chat attachments](kadan/chat-attachments.md) expectations describe the separate upload and submission extraction. These do not establish persistent projects or existing-document editing. The focused [file discovery](kadan/opening-workspace-files.md) extraction builds on the current transfer capability without adding project or existing-document editing.

## Intended experience and old reconciliations

The direction in [#392](https://github.com/ghalrym/Kadan/pull/392) and [#416](https://github.com/ghalrym/Kadan/pull/416) is to let each agent manage its own memory and persona, with users viewing retained memory rather than maintaining notes for the agent. Workspace documents are work products, with hierarchy separate from memories, personas and conversations. Users should not need to write and select an agent's persona for each response. Hiding a persona editor alone would not supply curation.

Current master now supplies model-directed [memory management](kadan/memories.md), [owned personas](kadan/personas.md), automatic persona use in later text work and new voice calls, and the [Documents browser](kadan/workspace.md). Neither curation on a schedule nor automatic recall on every response is promised. The unpublished reconciliation was also reviewed as historical context; its manual-only persona and pre-Documents descriptions are superseded by these current pages. It is not a separately approved specification.
