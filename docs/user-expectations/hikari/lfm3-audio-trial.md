# Experimental LFM3 audio calls

An optional trial lets applications explicitly choose LFM3-Audio-2B for a call. The regular call path remains available. The trial is disabled by default and requires the operator to enable its worker and API support. Users must review its model license and confirm its download through Hikari before starting. Opening a call does not accept licenses or download the model.

The trial uses the existing call connection, interruption and playback acknowledgements. It recognizes each completed English utterance, then generates a reply with both text and speech. Each whole reply is buffered as one audio segment before delivery. Speaking interrupts that turn, and only a fully played, acknowledged reply is retained in the next turn's context. Calls keep the same bounded recent history and discard it on disconnect.

This adapter does not expose live transcription, incremental speech playback, tools, voice cloning or simultaneous listening and generation inside the model. Its voice is generated by LFM3 rather than the regular Ryan voice. It does not promise full duplex inference, response latency, quality or physical memory fit. The BF16 runtime and actual calls require manual validation on the target GPU; unit tests do not establish those capabilities. Missing worker support, unavailable checkpoints, oversized context and incomplete model outputs produce errors rather than falling back to another model.

See [ordinary voice calls](voice-calls.md) for the call lifecycle and [trial architecture](../../architecture/hikari/worker-lfm3-audio.md) for setup and validation.
