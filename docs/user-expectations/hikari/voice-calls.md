# Live voice calls

Hikari lets applications open spoken conversations directly, without a Kadan agent. Every call uses the fixed LFM3-Audio-2B checkpoint for recognition, reply text and speech. There is no call-backend choice or enable switch. The worker must be available and the checkpoint must already have been downloaded after explicit license acknowledgement. Starting a call never accepts a license, downloads a model or substitutes another model. Readiness confirms that the session can begin, not that inference will fit or succeed.

The client supplies instructions, captures completed utterances, plays returned audio and reports playback progress. Hikari does not capture a microphone, detect speech onset or control speakers. Browser permission, recording controls and silence detection belong to the client. Calls have no agent tools or automatic access to Tsuchi resources.

Each new turn begins by interrupting the previous turn, including before the first utterance. Hikari cancels the previous response and waits for confirmed executor cleanup before acknowledging the interruption. Temporary utterance files are removed before cleanup is acknowledged. The client must stop and discard old audio locally and ignore results belonging to older turns. Each turn accepts one utterance; starting another requires a newer turn. Cancellation can take time and does not undo audio already heard.

The default reply is text plus one complete buffered audio segment. Playback starts only after the reply finishes generation and passes completion checks. This does not provide live transcription, incremental speech streaming, voice cloning or simultaneous listening and generation inside the model. English utterances are limited to twenty seconds and speech to sixty seconds per turn. Oversized or incomplete outputs fail explicitly. Loading, accuracy, audible quality, latency and maximum-context physical fit need review on the target machine.

The client acknowledges segments in order, only after each has fully played. Hikari carries only acknowledged assistant text into the next turn's context. Missing acknowledgements can make it forget replies the user heard; acknowledging unplayed audio can make it assume the user heard words they did not. Generation finishing does not mean playback has finished. A recognized utterance stays in context if its reply later fails or is interrupted.

Calls retain up to twelve recent whole messages only for that connection. The complete retained prompt and output share the audio model's context; overflow reports an error rather than silently cropping a message. Ending, disconnecting or an inference failure cancels pending work and discards the session history. Reconnecting starts a new call without replay. Invalid input or playback acknowledgements report an error and close the call. An utterance with no recognized text can finish without a reply.

During a call, its audio worker participates in Hikari's normal physical memory admission and cleanup. This does not promise residency, concurrent inference or sufficient memory for every request. Ending, disconnection or error restores ordinary inference priority and idle expiry.

Standalone [Whisper transcription](transcription.md), optional S1 formatting and [Qwen text to speech](text-to-speech.md) remain available through their existing APIs and playgrounds. Their models and settings are independent of calling. Hikari has no dedicated live-call playground UI; [Kadan voice calls](../kadan/voice-calls.md) provide the browser controls.
