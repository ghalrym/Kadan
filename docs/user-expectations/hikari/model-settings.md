# Model settings and downloads

Kadan Server's [AI models](../kadan-server/ai-models.md) lists the intended model for each ability, its download state and its download size. Abilities appear in this order: Chat & thinking, Voice calls, Images, Dictation, Dictation cleanup and Reading aloud. Models missing from the connected workers show **Not running**. **Download everything** downloads every missing model at once; each ability that is not downloaded also has its own **Download** button for fetching just that model. The confirmation shows the combined size of the models being downloaded and any license notices for them to review and accept. Only those models are requested. Downloads can wait, fail or remain incomplete; completion confirms acquisition, not that a model is loaded or a request will fit the machine.

AI models shows each model's progress. Percentages are estimates; the completed state confirms success. **Download everything** also retries failed or cancelled downloads without downloading completed models again, and each stopped ability offers **Try again**. Other models can be started while accepted downloads continue. Completed, active and unavailable models have no download button. Download sizes use verified totals when available; catalog estimates are used until the exact size is known. These sizes describe downloaded files, rather than loaded memory or generated files.

Saving the transcription formatting preference requires a connected native model store that can retain it. If none is available, Hikari reports an error instead of confirming a save through a language or audio worker.

Closing Kadan Server's pages keeps accepted downloads running. After a failed or timed-out request, refresh model state before retrying because some downloads may already have started.

AI models also lets users connect a Claude or ChatGPT subscription and switch chat (including screenshots) or image generation to it; see [Subscription language providers](subscriptions.md). Under **Advanced**, users choose the local Inkling 2 Mini size (**Smaller** is Q4, **Higher quality** is Q8) and content filter (**Standard**, or **Unfiltered** for the abliterated variant). Switching variants updates the active checkpoint in the list so its download state and size are shown and can be downloaded if not already on disk; previously downloaded variants stay on disk. Hikari has no hardware tiers or arbitrary per-machine model choices. Language (including screenshot vision and single-pass decisions) uses Inkling 2 Mini, voice calls use LFM3-Audio-2B, images use FLUX.2 Klein 4B, speech uses Qwen3-TTS CustomVoice, transcription uses Whisper medium, and formatting uses S1-mini. All require their own available worker and verified checkpoint. Inference never starts a missing-model download; review the licenses and explicitly start downloads in AI models first. Enabling or connecting a worker does not download its model. Earlier model files remain on disk and are not deleted by this change.

Downloaded checkpoints persist in their model store across ordinary container restarts. Deleting that store loses them. Hikari verifies downloads before treating a checkpoint as complete; users must not modify completed checkpoints externally or share one store between independent installations. With [remote workers](remote-workers.md), model files reside on the computers serving the workloads.

See [Model loading and context](model-lifecycle.md) for loaded-state behavior and [Settings architecture](../../architecture/hikari/model-settings.md) for download controls and saved settings.
