# Model settings and downloads

Hikari's Settings lists the intended model for each capability, its download state and estimated storage use. Capabilities appear in this order: Language, Decisions, Vision, Voice calls, Image, Speech to text, Speech formatter, Text to speech and Video. Models missing from the connected workers are shown as unavailable. **Download models** downloads every missing model at once; each row that is not downloaded also has its own **Download** button for fetching just that model. The confirmation shows the combined size of the models being downloaded and any license notices for them to review and accept. Only those models are requested. Downloads can wait, fail or remain incomplete; completion confirms acquisition, not that a model is loaded or a request will fit the machine.

The page shows each model's progress. Percentages are estimates; the completed state confirms success. **Resume downloads** retries failed or cancelled downloads without downloading completed models again, and each failed row offers **Retry**. Other models can be started while accepted downloads continue. Completed, active and unavailable models have no download button. Download sizes use verified totals when available; catalog estimates are labelled **estimated**, and unavailable sizes say **Size unknown**. These sizes describe downloaded files, rather than loaded memory or generated files.

Saving the transcription formatting preference requires a connected native model store that can retain it. If none is available, Hikari reports an error instead of confirming a save through a language or audio worker.

Closing the page keeps accepted downloads running. After a failed or timed-out request, refresh model state before retrying because some downloads may already have started.

Hikari has no hardware tiers or per-machine model choices. Language uses LFM3 1.7B, voice calls use LFM3-Audio-2B, vision uses LFM3-VL 2B, images use Qwen-Image Turbo, video uses H3 Turbo, speech uses Qwen3-TTS CustomVoice, transcription uses Whisper medium, formatting uses S1-mini, and decisions use d1 on CPU. All require their own available worker and verified checkpoint. Inference never starts a missing-model download; review the licenses and explicitly start downloads in Settings first. Enabling or connecting a worker does not download its model. Earlier model files remain on disk and are not deleted by this change.

Downloaded checkpoints persist in their model store across ordinary container restarts. Deleting that store loses them. Hikari verifies downloads before treating a checkpoint as complete; users must not modify completed checkpoints externally or share one store between independent installations. With [remote workers](remote-workers.md), model files reside on the computers serving the workloads.
