# Speech synthesis worker

Standalone `tts` jobs use the fixed `lfm3-audio-2b-bf16` checkpoint through the LFM3 audio worker and the existing queue/memory owner. `SpeechTask` and the public speech request carry `script`, explicit checkpoint, language/locale and gender. The public model choices contain the pinned card's nineteen locale choices for eighteen languages, and female/male genders. Qwen CustomVoice speaker names and delivery-instruction fields are not accepted or relabelled.

The worker uses the exact pinned TTS prompt: the selected language and gender in the TTS system instruction, the known script as the user message and an assistant audio-start prefill. It uses a fresh generation cache, remaining context budget and the bundled codec. The model's complete terminal output, pure-TTS control markers and finite 24-kHz PCM are checked before returning audio. Its existing callback limits speech to sixty seconds before expensive waveform decoding. A default language is American English and default gender is female; these are request choices rather than a named identity or cloned speaker.

The result contains the selected language/gender, known script, completed WAV, sample-derived duration and model metadata. This describes the requested synthesis, not an independent claim that the waveform pronounced every word correctly. No inference runs in the API. Cancellation terminates and joins the granted disposable executor, and incomplete output is never published as a completed clip.

The model license and pinned custom-code notice still require the existing user-approved download flow. No new credentials or license acceptance is implied by listing the model. Actual standalone speech, language quality, audible playback, cancellation and resource fit require manual validation. Whisper file transcription remains separate until a real replacement demonstrates the required behavior.
