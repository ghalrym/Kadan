# Persona instructions

Tsuchi owns each agent's canonical persona through nullable `Agent.persona_id`. The target is a normal, versioned persona resource in that agent's namespace. Existing named personas are never chosen by title, age or tag. The additive agents-column migration leaves existing agents without a canonical persona; they continue using the shared instructions until one is saved. See [Personas](../../user-expectations/kadan/personas.md) for observable behavior.

`GET /api/agents/{key}/persona` returns that active resource, or null when the pointer has never been assigned. `PUT` requires `title`, `markdown` and `expected_version`. Null version creates the first resource and assigns its pointer in one write transaction. A numeric version requires an existing matching resource. Competing initial saves and stale versions conflict. Titles are trimmed, nonblank and limited to 200 characters; Markdown must be nonblank and at most 16,000 characters. Updates preserve resource identity, links, tags, sources and attachments and append the ordinary revision history. Missing, trashed or wrong-kind pointer targets fail explicitly; restoring the same resource restores its use.

Kadan's `read_persona` and `update_persona` tools use the running agent's namespace without a model-supplied agent or resource ID. They are available without a configured computer. Reads may repeat after restart; uncertain writes return a tool error and are not replayed. Ownership is checked immediately before starting a write. A cancellation or lease change after the request starts cannot undo a committed Tsuchi save. Read-before-write versions protect against concurrent edits; storage failures and conflicts become tool results.

Context preparation appends the owned persona to the shared instruction file, followed by any explicitly selected persona. Identical IDs are included once. Selection stays a per-message input and is not resolved into the canonical ID at enqueue time, preserving submission retry identity. Newly prepared image-event runs use the current canonical persona too. The completed instruction snapshot is persisted with the run, so recovery does not substitute later edits. Both personas count against the existing context budget; an oversized instruction set fails rather than truncating instructions.

The existing named-persona editor and selection remain independent. Its updates use resource versions and preserve unrelated metadata. The browser selection resets when the chat view opens. Voice calls retain their separate instruction path and do not read the owned persona.
