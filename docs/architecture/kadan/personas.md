# Persona instructions

Tsuchi owns each agent's single canonical persona through nullable `Agent.persona_id`. The target is a normal, versioned persona resource in that agent's namespace. Existing agents without a canonical persona continue using the shared instructions until one is saved. See the user expectations for [personas](../../user-expectations/kadan/personas.md).

Kadan exposes each agent's single persona through `GET /api/agents/{key}/persona` and `PUT /api/agents/{key}/persona`, proxied to Tsuchi's owned-persona endpoint. `GET` returns the active resource or `null` when none has been saved yet. `PUT` accepts `markdown`, `expected_version`, and optional `title` (defaulting to the existing persona title or the agent's name when omitted). Null `expected_version` creates the first resource and assigns `Agent.persona_id` in one write transaction; a numeric version requires an existing matching resource. Competing initial saves and stale versions return 409. Markdown must be nonblank and at most 16,000 characters. Updates preserve resource identity, links, tags, sources, attachments and revision history. Missing, trashed or wrong-kind pointer targets fail explicitly; restoring the same resource restores its use.

The Kadan web UI opens a Markdown editor modal (`PersonaEditor.tsx`, with Write and Preview views) from the **Persona** button under **Call** on the agent's card and from the Agent page. Kadan does not expose multi-persona libraries or per-message persona selection.

Kadan's `read_persona`, `update_persona`, and `rename_self` tools operate exclusively on the running agent's own record without a model-supplied agent or resource ID (`title` and `expected_version` are optional on `update_persona`; when `expected_version` is omitted, the runner resolves the current persona version internally under its run lease so updates succeed in a single tool call, while an explicit `expected_version` preserves strict optimistic conflict checks; `rename_self` reads the agent's current name and writes through `PUT /api/agents/{key}` with `expected_name`). Reads may repeat after restart; uncertain persona saves and self-renames return a tool error and are not replayed. Ownership is checked immediately before starting a write. A cancellation or lease change after the request starts cannot undo a committed Tsuchi save. Explicit version checks and expected-name checks protect against concurrent edits; storage failures and conflicts become tool results.

Context preparation reads the agent record (`GET /api/agents/{key}`) and its owned persona, then appends natural character framing (`You are "{agent.name}"...`) right before the persona (or warm standalone framing when no persona is saved) to the shared instruction file, followed by the epoch-frozen Core Memories snapshot and any rolling `compacted_summary`. Newly prepared image-event runs use the current agent name and canonical persona too. The completed instruction snapshot is persisted with the run, so recovery does not substitute later edits. The persona counts against the existing context budget; an oversized instruction set fails rather than truncating instructions.

## Voice calls

The browser opens `/api/agents/{key}/calls` and sends `{type: "start"}`. Kadan requires this first message within 15 seconds and reads the agent record, canonical persona, and active Core Memories through `LocalServices.agent`, `LocalServices.agent_persona`, and `LocalServices.core_memories_snapshot`. The instruction snapshot uses a short spoken-conversation base plus the same natural character framing (`You are "{agent.name}"...`), saved persona, and Core Memories rather than the shared tool-bearing instruction file. Kadan rejects combined base + persona instructions above Hikari's 8,000-character limit before connecting to Hikari; the persona is never truncated, and Core Memories are trimmed to fit whatever space remains under 8,000 characters.

Kadan sends the resolved `{type: "start", instruction: string}` upstream, then hands the socket to the existing bidirectional relay. Setup owns cleanup until this handoff, including a failed or cancelled initial send. The snapshot lives only in the call, without run persistence or persona writes. See the [voice call expectations](../../user-expectations/kadan/voice-calls.md) for caller behavior and limitations.
