# Portable workflows

A workflow is a Tsuchi `space` resource carrying the `workflow` tag. Its title, Markdown instructions, revisions, trash and agent namespace use the existing resource store. Kadan exposes scoped list, read and create routes under `/api/agents/{key}/workflows`; list pagination scans Space pages before filtering the tag. Editing and revision recovery remain in Tsuchi.

The portable JSON bundle has exactly `schema_version: 1`, `title` and `instructions`. Validation forbids extra fields, blank text, titles over 500 characters and instructions over 12,000 characters. The frontend bounds file bytes before parsing and presents the full instructions before explicit Save. Creation returns a confirmed initial Space version matching the submitted text; an error leaves creation uncertain and requires a successful list check before another Save. A synchronous client lock prevents duplicate concurrent saves.

Run creation carries `workflow_id` and `workflow_version` separately from the fresh user message. In the same Tsuchi transaction that appends the task and queues its run, storage checks the same agent, active Space, tag, version and instruction budget, then copies identity, title, version and instructions into `AgentRun.workflow`. Repeating the message ID with the same selection returns that original snapshot without rereading the source. A different selection conflicts. Image follow-ups inherit the snapshot; resumed work retains it. Normal sends and saved notes do not select a workflow. The Chat outbox retains the selection with its original message ID.

The runner adds a static method-only hint and exposes `read_workflow`. The snapshot is returned through the existing structured tool-result path: the durable transcript's tool-result envelope becomes a LangChain `ToolMessage`, then uses the checkpoint's existing tool-response serialization. Template text is never appended to user content or substituted for system instructions. Templates add no authorization or permission system, and cannot replay historical approvals. They contain no installed code, credentials, schedules or event bindings.
